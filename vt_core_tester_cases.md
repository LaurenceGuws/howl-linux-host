# VT Core Tester Cases

This file tracks small manual checks for `vt-core` functionality once it is integrated through `howl-term` and exposed by `howl-linux-host`.

Use plain shell commands first.
Prefer `cat -v` when validating raw reply bytes or negotiated key output.

## Slice 1: Reply Path

Status:
- landed in `howl-term`
- available to Linux-host through the normal PTY runtime path

Goal:
- verify that terminal replies generated by `vt-core` are actually written back to the PTY

Test flow:
1. Start Howl.
2. Run `cat -v`.
3. In another shell line or after restarting `cat -v` as needed, run each command below.

Commands:
- `printf '\033[5n'`
- `printf '\033[6n'`
- `printf '\033[c'`
- `printf '\033[>c'`
- `printf '\033[?1004$p'`
- `printf '\033[?2004$p'`

Expected output in `cat -v`:
- `^[[0n`
- `^[[<row>;<col>R`
- `^[ [ ? 62 ; 22 c` rendered in caret form
- `^[ [ > 1 ; 10 ; 0 c` rendered in caret form
- `DECRPM` replies for supported modes

Notes:
- exact cursor row/column depends on where `cat -v` is running
- unsupported queried modes should still return the tracked unsupported reply shape where implemented

## Slice 2: Typed Special Keys

Status:
- landed in Linux-host SDL input path
- special keys now route through `howl-term.publishInputKey()` instead of SDL hardcoded escape tables

Goal:
- verify that negotiated key behavior comes from `vt-core`, especially app-cursor mode

Test flow:
1. Start Howl.
2. Run `printf '\033[?1h'`.
3. Run `cat -v`.
4. Press Up, Down, Left, Right.
5. Exit `cat -v`.
6. Run `printf '\033[?1l'`.
7. Run `cat -v` again.
8. Press Up, Down, Left, Right.

Expected output:
- with `?1h`: `^[OA`, `^[OB`, `^[OC`, `^[OD`
- with `?1l`: `^[[A`, `^[[B`, `^[[C`, `^[[D`

Additional checks:
- Home, End, Insert, Delete, PageUp, PageDown still emit working sequences
- F1-F12 still emit working sequences
- Shift+Tab should now negotiate through the typed key path instead of relying on a raw SDL byte table

## Slice 2B: Mouse Reporting

Status:
- landed in Linux-host through typed mouse events
- cell mapping and terminal encoding now live in `howl-term`
- local wheel scrollback only applies when terminal mouse reporting is inactive

Goal:
- verify that click/move/wheel reports go to the terminal when enabled
- verify that wheel falls back to local scrollback when mouse reporting is disabled

Suggested harness:
- prefer `/home/home/personal/projects/howl/utils/howl-microscope` for iteration if you want richer host-side inspection
- plain shell plus `cat -v` is still enough for the basic protocol checks

Test flow: terminal mouse reporting on
1. Start Howl.
2. Run:
```sh
printf '\033[?1002h\033[?1006h'; cat -v
```
3. Click, drag, and release inside the terminal.
4. Use the mouse wheel inside the terminal.

Expected output:
- SGR mouse reports such as `^[[<...M` and `^[[<...m`
- wheel should emit terminal mouse reports instead of scrolling local scrollback

Test flow: any-motion reporting
1. Run:
```sh
printf '\033[?1003h\033[?1006h'; cat -v
```
2. Move the mouse across terminal cells.

Expected output:
- motion reports should appear without requiring a pressed button

Test flow: local scrollback fallback
1. Run:
```sh
printf '\033[?1000l\033[?1002l\033[?1003l\033[?1006l'
```
2. Produce enough output to create history.
3. Use the mouse wheel.

Expected output:
- wheel should scroll local terminal scrollback again
- no mouse-report sequences should be sent to the app

## Slice 2C: Focus Reporting

Status:
- landed in Linux-host through the terminal focus path
- effective terminal focus combines desktop/window focus with active widget/tab focus

Goal:
- verify that focus reports are sent only when the terminal app enables focus reporting

Test flow:
1. Start Howl.
2. Run:
```sh
printf '\033[?1004h'; cat -v
```
3. Move desktop focus away from the Howl window.
4. Refocus the Howl window.

Expected output:
- focus out should emit `^[[O`
- focus in should emit `^[[I`

If focus reporting is not enabled:
- focus changes should not write focus-report sequences to the app

Focus UI behavior:
- active input target should show the terminal's preferred cursor shape
- unfocused terminal should show a hollow block cursor when the VT cursor is visible
- effective input focus is: desktop/window focus AND active widget/tab focus

For host-level focus and mouse iteration where shell-only testing is awkward:
- prefer running `/home/home/personal/projects/howl/utils/howl-microscope`
- use it as the live inspection harness for window focus changes, widget focus changes, and future mouse-reporting checks

## Slice 3: Bracketed Paste

Status:
- landed in Linux-host through an explicit paste shortcut path
- paste is now emitted by `howl-term`, so bracket wrappers come from `vt-core` mode state

Test flow:
1. Start Howl.
2. Copy some plain text into the desktop clipboard.
3. Run `printf '\033[?2004h'`.
4. Run `cat -v`.
5. Press the configured paste shortcut.

Default paste shortcuts:
- `Ctrl+Shift+V`
- `Shift+Insert`

Expected output:
- pasted text should be wrapped with `^[[200~` before it
- pasted text should be wrapped with `^[[201~` after it

If bracketed paste is not enabled:
- the same paste shortcut should still paste text
- wrapper sequences should be absent

## Slice 4: OSC 52 Clipboard Policy

Status:
- landed in Linux-host with an explicit host policy surface
- default policy is `deny`

What OSC 52 is:
- OSC 52 is a terminal escape sequence that asks the terminal application to write text into the system clipboard
- it is not the same thing as normal user paste
- the terminal app emits it; the host decides whether to honor it

Current config:
- `term.clipboard.osc_52 = "deny" | "allow"`
- default in Linux-host is `"deny"`

Test flow with deny:
1. Start Howl with default config.
2. Run `printf '\033]52;c;SGVsbG8=\a'`.
3. Paste into another app.

Expected result with deny:
- clipboard should remain unchanged

Test flow with allow:
1. Change `term.clipboard.osc_52` to `"allow"` in `assets/default_config/init.lua` or your effective config.
2. Restart Howl.
3. Run `printf '\033]52;c;SGVsbG8=\a'`.
4. Paste into another app.

Expected result with allow:
- system clipboard should now contain `Hello`

Notes:
- `SGVsbG8=` is base64 for `Hello`
- current host behavior supports clipboard writes, not OSC 52 queries

## Slice 5: OSC 8 Hyperlinks

Status:
- OSC 8 link IDs flow from `vt-core` through `howl-term` and render-core surface cells
- Linux-host can resolve a clicked cell to its URI
- default link opening policy is `disabled`

Current config:
- `term.links.open = "disabled" | "system"`
- default in Linux-host is `"disabled"`

Test flow with disabled:
1. Start Howl with default config.
2. Run `printf '\033]8;;https://example.com\aLINK\033]8;;\a\n'`.
3. `Ctrl+left click` on `LINK`.

Expected result with disabled:
- no system opener should launch

Test flow with system opener:
1. Change `term.links.open` to `"system"` in `assets/default_config/init.lua` or your effective config.
2. Restart Howl.
3. Run `printf '\033]8;;https://example.com\aLINK\033]8;;\a\n'`.
4. `Ctrl+left click` on `LINK`.

Expected result with system opener:
- the system URL opener should receive `https://example.com`

Notes:
- terminal mouse reporting still takes priority when an app has enabled it
- hover cursor/underline polish is still future UX work
